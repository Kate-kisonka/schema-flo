# Roadmap schema-flo — план задач по ролям

Контекст: приложение готовится к показу **небольшой аудитории** (близкий круг, не публичный запуск). Отсюда приоритет: сначала безопасность и то, обо что споткнётся новый человек; масштаб (нагрузка, кеши, горизонтальное масштабирование) — вне скоупа, не переинженерим.

Как пользоваться: оркестратор берёт задачу, отдаёт её роли-владельцу (см. «Оркестрация» в CLAUDE.md). Задачи с двумя ролями — сначала primary, потом secondary. После правок dev-роли — прогон `tester` по сценарию; перед Фазой 1 «показать людям» — `security-reviewer`. Ни один агент не коммитит сам.

Обозначения: **DoD** — definition of done (когда считать готовым). Пункты сверены с ревью кода и продукта от 2026-07-08.

---

## Фаза 1 — перед показом людям (безопасность + очевидные спотыкания)

### F1-1. Автосохранение черновика дневника
- **Роль:** frontend-dev
- **Почему:** дневник заполняется в 4 шага, «Сохранить» только на последнем. Свернула вкладку на шаге 2 — всё потеряно. Для ежедневного ритуала это главное трение.
- **DoD:** незавершённый ввод (настроение/тело/схемы/заметки) переживает перезагрузку страницы; при сохранении дня черновик очищается; проверено в живом UI.

### F1-2. Убрать выдуманный день цикла при офлайне
- **Роль:** frontend-dev
- **Почему:** `dbCycle.get()` при упавшем API молча подставляет `cycleDay: 14` (services/db.js) — пользователь видит ложный день цикла вместо «нет связи».
- **DoD:** при ошибке загрузки состояния UI показывает нейтральное «данные не загрузились», а не подставное число; happy path не сломан.

### F1-3. Подтверждение выхода
- **Роль:** ui-ux-designer (взаимодействие) → frontend-dev (провод)
- **Почему:** «🚪 Выйти» стоит прямо в навбаре рядом с вкладками — случайный тап разлогинивает.
- **DoD:** выход требует подтверждения (или перенесён из основной навигации); проверено на mobile-ширине.

### F1-4. Применить rate-limiting логина
- **Роль:** backend-dev
- **Почему:** брутфорс пароля ничем не сдержан. Готовый патч лежит в `patches/rate-limit-login.patch` (пути внутри старые — корневой `backend/`, накладывать на `application/backend/` с поправкой пути), нужно добавить `express-rate-limit` в package.json.
- **DoD:** повторные неудачные логины с одного IP начинают отклоняться; обычный вход работает; патч после применения удалён.

### F1-5. Закрыть «чёрные ходы» (связанная задача)
- **Роли:** devops (compose) + backend-dev (CORS/OAuth env) + frontend-dev (VITE_API_URL)
- **Почему:** backend :3001 и frontend :5173 опубликованы наружу, `VITE_API_URL` смотрит на прямой порт мимо прокси. Делать только целиком: убрать publish портов + `VITE_API_URL=http://localhost` + выверить `ALLOWED_ORIGINS`/`FRONTEND_URL` (сейчас со слэшем на конце — не совпадёт с заголовком Origin) + OAuth redirect. См. «Известные незакрытые моменты» в CLAUDE.md.
- **DoD:** приложение полностью работает через `http://localhost` (:80); прямые порты 3001/5173 наружу не публикуются; вход, дневник, Google OAuth проходят; `docker compose config` зелёный.

### F1-6. Аудит безопасности перед показом
- **Роль:** security-reviewer (только отчёт)
- **Почему:** данные о психике и цикле — особая категория; перед тем как их увидит кто-то кроме владелицы, нужен проход по изоляции user_id, JWT/OAuth, секретам, `npm audit`.
- **DoD:** отчёт с 🔴/🟠/🟡; все 🔴 либо закрыты, либо осознанно приняты владелицей.

## Фаза 2 — глубина продукта для реального использования

### F2-1. Экран-представление + приватность
- **Роли:** ui-ux-designer (текст/вид) + frontend-dev (провод)
- **Почему:** сейчас первый экран — «Войди в аккаунт», без слова о том, что это и что с данными. Для нового человека приложение немое.
- **DoD:** до/на экране входа — 2–3 фразы о сути (дневник состояния: цикл × схемы × эмоции) и явная строка о приватности данных; тон совпадает с остальным приложением.

### F2-2. Адаптивная длина цикла
- **Роль:** frontend-dev (нужно сначала продуктовое решение по модели данных)
- **Почему:** `getPhase()` раздаёт фазы по жёсткой сетке 1–28, но реальные циклы 24–35 дней — и все физиологические подсказки «что в теле/психике» уезжают. `avgCycleLength` уже посчитан, но фазами не используется.
- **DoD:** фазы считаются от реальной/средней длины цикла пользователя, ИЛИ (минимальный вариант) в UI явно указано «примерная модель 28 дней»; решение о варианте зафиксировано с владелицей до реализации.

### F2-3. Раскрыть описания схем
- **Роли:** ui-ux-designer (аффорданс) + frontend-dev (провод)
- **Почему:** объяснение схемы открывается по двойному клику (HomeScreen.jsx) — на телефоне неочевидно и недискавербл; порог терминологии для новой аудитории высок.
- **DoD:** к описанию схемы есть явный видимый способ доступа (иконка ⓘ / одинарный тап на область) на тач-экране; двойной клик не единственный путь.

### F2-4. Читаемость и доступность
- **Роль:** ui-ux-designer
- **Почему:** шрифты 9–11px по всему UI, тач-цели вроде точек-шагов 7px, эмодзи-кнопки без aria-label.
- **DoD:** базовый текст не мельче ~13px, интерактивные цели ≥ ~40px, у иконок-кнопок есть aria-label; проверено в трёх viewport (mobile/tablet/desktop).

## Фаза 3 — здоровье кода (пользователь не видит)

### F3-1. Единый HTTP-клиент на фронте
- **Роль:** frontend-dev
- **Почему:** `authApi.js` и `services/db.js` дублируют `request()`-хелпер, строка `"auth_token"` захардкожена в двух местах.
- **DoD:** один общий модуль-клиент (токен + обработка ошибок в одном месте); оба сервиса используют его; сценарии не сломаны.

### F3-2. Прямой POST дневника без лишнего запроса
- **Роль:** frontend-dev
- **Почему:** `dbDiary.upsert()` делает GET «есть ли запись» → потом POST/PATCH, хотя сервер уже умеет `ON CONFLICT DO UPDATE`.
- **DoD:** сохранение дня — один POST; запись за дату не дублируется; гонки при двойном клике нет.

### F3-3. PATCH-семантика для /api/state
- **Роль:** backend-dev
- **Почему:** PUT требует все поля, поэтому `useCycle` и `useSilence` делают read-modify-write — два таба/медленная сеть перезатирают друг друга (last-write-wins).
- **DoD:** сервер обновляет только присланные поля; параллельное изменение цикла и «тишины» не затирает соседнее поле.

### F3-4. Разбить server.js на роутеры
- **Роль:** backend-dev
- **Почему:** ~700 строк в одном файле (auth/diary/cycle/practices/import); каждая фича усложняет.
- **DoD:** эндпоинты вынесены в `routes/*.js` через `express.Router()`; поведение и пути `/api/*` не изменились; стек поднимается.

### F3-5. Первые тесты
- **Роли:** frontend-dev (`utils.js`: фазы, даты) + backend-dev (валидация входа)
- **Почему:** тестов нет; чистые функции — идеальные первые кандидаты, дёшево и страхуют рефакторинг Фазы 3.
- **DoD:** тест-раннер настроен; покрыты `getPhase`/`avgCycleLength`/`toDateKey` и валидаторы (`isIsoDate`, `toSafeInt`); тесты зелёные.

## Оркестрация

- **Порядок:** Фаза 1 целиком → показ аудитории → Фазы 2 и 3 можно чередовать. Внутри Ф1 независимы, кроме F1-5 (делать связкой) и F1-6 (последней).
- **Гейты ревью:** после каждой content-правки dev-роли — `tester` по затронутому сценарию; F1-4 и F1-5 (auth/сеть) — обязательно через `security-reviewer` до показа.
- **Территории:** конфликтов нет; задачи с двумя ролями (F1-3, F1-5, F2-1, F2-3) координирует оркестратор — primary делает свою часть, secondary подхватывает по явной передаче.
- **Вне скоупа (небольшая аудитория):** масштабирование, кеш-слои, очереди, CDN, многоязычность. Не заводить без явного запроса.
